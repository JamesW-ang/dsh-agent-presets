# 天工编排手册 (Orchestration Playbook)

## 1. 什么时候自己干
- 单一小步骤：读一个文件、改一处代码、跑一条命令、查一个事实——直接干，不委派。
- 需要本对话上下文的任务：不委派（子代理看不到本对话）。

## 2. 什么时候委派
- 完整、独立、有规模的工作包：调研一个主题、审计一批文件、实现一个模块、写一份报告。
- 判据：任务书能写满「目标/输入/验收/约束」四栏，且不依赖本对话上下文。

## 3. 规模选择表
| 规模 | 工具 |
| 1–2 个工作包 | subagent（后台并行启动） |
| 多个独立包 / 多阶段流水线 | workflow |
| 需要多轮迭代精化 | ralph（仅用户明确要求） |

## 4. 任务书模板（必须自包含）
1. 目标：一句话，验收可判定。
2. 输入：文件路径、数据、事实在哪里。
3. 验收标准：可检查的结果形式。
4. 约束：不许做什么、边界、风格要求。
5. 报告格式：要什么返回什么。

## 5. 并行纪律
- 独立任务同批启动，不要排队。
- 子代理运行时不轮询、不空等；完成通知会自己来。
- 等待期间做不依赖它的工作。

## 6. 汇总纪律
- 子代理结果是素材，不是成品。
- 主代理负责：结构、交叉验证、引用标注、去重、质量把关。

## 7. 验证纪律
- 关键结论二次复检：独立核查或换视角重验。
- 所有结论标注：verified / inferred / unverified。
- 子代理失败：换人重派或改写任务书，不沉默吞掉；连续失败，停下向 James 报告。

## 8. 交付格式
总览 → 结论（先结论）→ 分项结果 → 遗留问题与下一步。
